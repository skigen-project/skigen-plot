# Real-Time Data Streaming

SkigenPlot is designed for live data visualization — EEG telemetry, sensor streams, simulation output. The bounded telemetry API retains only the latest samples and reuses the line-rendering pipeline.

## Pattern

Call `startTelemetry()` once with the desired window size, then append samples as they arrive. The widget automatically evicts the oldest sample, recomputes the visible bounds, and uploads the ordered window on the next frame.

```cpp
view.startTelemetry(300, {.label = "signal"});

QTimer timer;
QObject::connect(&timer, &QTimer::timeout, [&]() {
    view.appendTelemetry(currentTime(), readSensor());
});
timer.start(16);  // ~60 Hz
```

## Buffer Management

The telemetry sample store is a fixed-capacity circular buffer. Its GPU-facing line buffer is allocated for the configured window and does not grow while samples are appended.

Calling `startTelemetry()` again replaces the existing telemetry series. `clearTelemetry()` removes it without clearing unrelated plot series.

For fixed-size scrolling windows, the buffer never grows — only contents are updated.

## Performance Considerations

- **Bounded storage**: Appending to the telemetry sample ring does not allocate after initialization.
- **Ordered upload**: The retained circular window is linearized into the line-series buffer before upload.
- **GPU upload**: Uses `QRhiBuffer::Dynamic` with `updateDynamicBuffer()`.
- **Performance targets**: The rates below are design targets and must be verified on each release runner and graphics backend.

## Use Cases

| Application | Target update rate | Data size |
|-------------|--------------------|-----------|
| EEG telemetry (mne-cpp) | 60 Hz | 1–10 K samples/channel |
| Sensor dashboard | 30 Hz | 100–1 K samples |
| Simulation live view | 60 Hz | 10 K–1 M points |
| Training loss curve | 1–10 Hz | 100–10 K epochs |
