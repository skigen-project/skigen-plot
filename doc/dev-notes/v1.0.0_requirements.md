# SkigenPlot v1.0.0 — Release Requirements

## Mission

Provide the ubiquitous, low-friction plotting standard for the C++ scientific
and ML ecosystem.  Think *matplotlib for C++*, but hardware-accelerated from
day one.

## Product Positioning

SkigenPlot v1.0.0 is a stable **single-axes scientific plotting engine**. It
must make the common path from Eigen data to an interactive or exported figure
reliable, predictable, and pleasant. It is not required to reproduce every
Matplotlib plot type or the complete `pyplot` state machine before release.

The long-term compatibility reference is the capability model documented by
[Matplotlib plot types](https://matplotlib.org/stable/plot_types/index.html)
and the [pyplot API](https://matplotlib.org/stable/api/pyplot_summary.html),
reviewed against Matplotlib 3.11.1. Compatibility means equivalent visual and
scientific workflows with idiomatic C++ APIs; it does not require Python
signature compatibility.

SkigenPlot should eventually match Matplotlib's broadly useful plotting,
axes, layout, annotation, color, interaction, and export capabilities. It
should exceed Matplotlib where a native GPU-first C++ design has a structural
advantage: large-data rendering, bounded streaming, predictable ownership,
typed Eigen/ranges integration, asynchronous upload, and interactive 3D.

## Scope (MVP)

### Supported Plot Types

| Type | Dimension | Input | Notes |
|------|-----------|-------|-------|
| Line plot | 2D | `VectorXf` × 2 (x, y) | Solid polyline, per-series colour |
| Scatter plot | 2D | `VectorXf` × 2 (x, y) | Circular point sprites via `gl_PointCoord` |
| Scrolling telemetry | 2D | Ring buffer / streaming `VectorXf` | Fixed-width sliding window |
| Point cloud | 3D | `MatrixXf` (N × 3) | Per-vertex colour, depth test |
| Surface mesh | 3D | Vertices (N × 3) + indices (M × 3) | Smooth shading via averaged vertex normals |

### Statistical & Filled 2D Plot Types

These are the highest-value additions for an ML / scikit-learn companion
library, ranked by urgency. They all build on a new **2D filled-triangle
pipeline** (`fillPipeline`, Triangles, no depth, alpha blend) — the single
piece of shared infrastructure that unblocks bars, histograms, area fills,
and box geometry.

All plot types in the two tables below are implemented and represented in the
rendered gallery. Lifecycle support differs by renderer and is tracked in the
essential usability table.

| Priority | Type | API | Input | Notes / ML use case |
|---|---|---|---|---|
| 1 | Histogram | `hist(v, bins)` | `VectorXf` + bin count | Auto-binning (uniform), counts or density; the primary data-exploration tool. |
| 2 | Bar chart | `bar(x, h)` / `barh(y, w)` | `VectorXf` × 2 | Feature importances, class counts, metric comparisons; categorical positions. |
| 3 | Heatmap | `imshow(M)` | `MatrixXf` (R × C) | Colormapped grid; confusion matrices, correlation matrices. Needs a colormap (viridis default). |
| 4 | Error bars | `errorbar(x, y, err)` | `VectorXf` × 3 | Symmetric vertical whiskers + caps; cross-validation score bands. |
| 5 | Filled area | `fillBetween(x, y0, y1)` / `step(x, y)` | `VectorXf` × {2,3} | ROC/PR curves, learning-curve confidence bands; triangle-strip fill between two y-series. |
| 6 | Box plot | `boxplot(groups)` | one `VectorXf` per group | Quartile box + median + whiskers + outliers; distribution comparison across groups / models. |
| 7 | Stem plot | `stem(x, y)` | `VectorXf` × 2 | Baseline-anchored impulses with markers; signal-processing / sparse-coefficient views. |
| 8 | Contour lines | `contour(Z, levels)` | `MatrixXf` (R × C) | Iso-lines via marching squares; classifier decision boundaries, density / loss surfaces. |
| 9 | Filled contour | `contourf(Z, levels, cmap)` | `MatrixXf` (R × C) | Colormapped filled bands between levels; smooth decision-region shading. |
| 10 | Violin plot | `violinplot(groups)` | one `VectorXf` per group | Gaussian-KDE density mirrored about each group axis; richer than a box plot for multimodal distributions. |
| 11 | Quiver | `quiver(x, y, u, v)` | `VectorXf` × 4 | Vector-field arrows (shaft + head); gradients, flow, embedding displacements. |
| 12 | Hexbin | `hexbin(x, y, gridsize, cmap)` | `VectorXf` × 2 | Hexagonally-binned 2-D density; large scatter sets without overplotting. |
| 13 | Pie chart | `pie(values)` | `VectorXf` | Proportional wedges (triangle fan); class balance / composition. |

**Contours.** `contour` extracts iso-lines at the requested levels (explicit
list or an evenly-spaced count between the data min/max) using the
marching-squares algorithm, emitting line segments through the existing grid
pipeline. `contourf` colours each value band with the chosen `Colormap` via
the per-vertex `fill2d` pipeline (cell-level quantisation for v1.0.0).

**Colorbar.** Heatmaps and filled contours can show a vertical `colorbar()`
legend: a thin colormapped strip beside the plot with min / mid / max tick
labels, rendered through the heatmap pipeline (data-space quad with per-vertex
colours) plus the text overlay.

**Colormaps.** Heatmaps introduce a `Colormap` concept exposing
`sampleColormap(Colormap, t) -> Eigen::Vector4f` over `t ∈ [0, 1]` and a
per-plot value→colour mapping with explicit or auto data range. Bundled maps:
perceptually-uniform `viridis` (default), `magma`, `plasma`; the diverging
`coolwarm`; linear `gray`; and the MATLAB classics `jet`, `hot`, `cool`,
`bone` (ported from MNE-CPP's DISPLIB ColorMap).

**Binning.** Histograms expose uniform binning with an explicit bin count or a
Sturges-rule default and support count or density rendering. An inspectable
histogram result containing computed bin edges and counts remains open.

### Public API Contract

* Accept `const Eigen::MatrixBase<Derived>&` on every data-facing entry point.
* Retain submitted data in GPU-ready float storage. Contiguous float inputs
  should require no more than one owned CPU copy before upload.
* Bridge any `std::ranges::contiguous_range` of arithmetic type into an
  `Eigen::Map` via a single-call helper.

### Essential v1.0 Usability Surface

The plot types above are necessary but not sufficient for a solid first
release. The following cross-cutting capabilities are release requirements
because they affect ordinary scientific workflows or public API stability.

| Capability | Status | v1.0 requirement | Matplotlib analogue |
|---|---|---|---|
| Series lifecycle | **Implemented** | Plot-creation methods return a stable `SeriesHandle`; supported data/style updates, visibility, and removal do not clear unrelated series. Field data updates are unsupported in v1 and return `false`. Invalidated handles fail predictably. | `Artist`, `Line2D.set_data`, `Artist.remove` |
| Legend | **Implemented** | Render labels from `PlotStyle::label`; support show/hide, automatic placement, and four corner placements. Unlabelled and hidden series are omitted. | `legend` |
| Axis limits | **Implemented** | Get/set/reset x and y limits independently. Explicit limits disable autoscaling for that axis until reset. Reversed limits intentionally invert an axis. Non-finite and equal endpoints are rejected. | `xlim`, `ylim`, `autoscale`, axis inversion |
| Axis scales | **Implemented** | Independent linear and base-10 logarithmic x/y scales. Limits remain in data units, reversed positive limits preserve inversion, pan/zoom operate in transformed space, and non-positive samples are omitted from logarithmic bounds and rendering. | `xscale`, `yscale`, `semilogx`, `semilogy`, `loglog` |
| Line styles | **Implemented** | Solid, dashed, dotted, and dash-dot lines use portable triangle strokes. Per-series line width, opacity, lifecycle style updates, screen-stable dash spacing, legend samples, and non-finite gaps affect rendered output. | `linestyle`, `linewidth`, `alpha` |
| Markers | **Implemented** | Circle, square, triangle, plus, and cross markers with configurable size. Circle, square, and triangle support filled/hollow rendering; plus and cross are stroked shapes. | `marker`, `markersize`, marker face/edge color |
| Input validation | **Implemented** | Empty inputs, mismatched vector lengths, invalid dimensions, non-positive bins/levels, non-finite values and bounds, and invalid indices have documented deterministic behavior. Vector and grouped statistical plots filter non-finite samples, filled areas preserve invalid gaps, pie uses finite positive weights, and mismatched vectors truncate deterministically. Heatmaps/contours mask invalid cells; point clouds and meshes validate shape, finite vertices, and mesh index ranges. | Matplotlib validation semantics |
| Data ownership | **Implemented** | Submitted series data is copied into owned float storage and remains valid after caller temporaries are destroyed. Updates must not leak CPU or GPU resources. | Artist-owned data |

Current staging status: stable handles and lifecycle operations are available
for line, scatter, histogram, bar, horizontal-bar, filled-area, step,
error-bar, stem, box, violin, quiver, and pie plots. Composite plot components
share one handle. Stored labels drive configurable legends. Extending handles
to separately buffered colormapped and contour plots remains open before the
series-lifecycle criterion is met.

Basic subplot grids, arbitrary annotations, vector export, date/category axes,
and the complete Matplotlib style grammar are intentionally post-1.0. Qt
applications can compose multiple `PlotView` widgets in layouts until the
native multi-axes API lands.

### Rendering Architecture

* All rendering through `QRhiWidget` (Qt ≥ 6.7).
* Backends: Vulkan (Linux/Android), Metal (macOS/iOS), Direct3D 12 (Windows).
* Scientific data geometry renders through QRhi pipelines. `QPainter` is
  permitted for text, labels, and widget overlays, but not for data series.
  `QGraphicsScene` and `QOpenGLWidget` are not used.
* Shaders compiled to `.qsb` via `qt_add_shaders()` at build time.
* Public headers forward-declare all QRhi types; `#include <rhi/qrhi.h>` is
  confined to `.cpp` translation units only.
* Multi-pipeline architecture:
  - `linePipeline` (LineStrip) — 2D line plots
  - `pointPipeline` (Points) — 2D scatter plots
  - `point3dPipeline` (Points, depth) — 3D point clouds
  - `meshPipeline` (Triangles, depth) — 3D mesh rendering
  - `gridPipeline` (Lines, alpha blend) — grid and axis overlays
  - `fillPipeline` (Triangles, no depth, alpha blend) — uniformly coloured
    filled 2D geometry for bars, histograms, area fills, and box plots
  - `heatmapPipeline` (Triangles, no depth, alpha blend) — interleaved
    position/colour geometry for heatmaps, filled contours, hexbins, and pies

### Grid and Axes

* Automatic tick computation via "nice number" algorithm.
* View bounds snap to nice tick boundaries for clean grid alignment.
* Grid lines rendered with alpha blending under data.
* Axis lines at x=0, y=0 (or edges) with perpendicular tick marks.
* `setGridVisible(bool)`, `setAxesVisible(bool)` API.

### Theming

* `Theme` struct: background, gridColor, axisColor, textColor, 6 series colors.
* `Theme::dark()` — deep navy background (#0c0a1a), skigen brand palette
  (cyan #06b6d4, violet #7c3aed, purple #a855f7).
* `Theme::light()` — clean white background (#f8fafc), darker series variants.
* `Theme::paper()` — clean publication layout: white background (#ffffff),
  light-gray solid gridlines (#b0b0b0 @ ~0.4 alpha), muted dark-gray
  spines/text (#262626), plain spines (no axis arrowheads), paired with the
  vivid Skigen categorical palette.
* `Theme::matplotlibStyle()` — the `paper()` layout with the canonical
  matplotlib `tab10` palette (tab:blue #1f77b4, tab:orange #ff7f0e,
  tab:green #2ca02c, tab:red #d62728, tab:purple #9467bd, tab:brown #8c564b);
  matches `matplotlib.pyplot` defaults exactly.
* **Palette / Theme are decoupled.** `enum class Palette { Skigen, Matplotlib }`
  selects only the series colours; `seriesPalette(Palette)` returns the six
  colours; `Theme::withPalette(Palette)` returns a copy of any theme with a
  swapped palette (layout kept); `PlotView::setPalette(Palette)` applies a
  palette live. Default palette is `Skigen`.
* `setTheme(const Theme&)` API; user color overrides take precedence.
* Default: dark theme. The rendered gallery / `saveThemed` emits `_paper.png`
  (white + Skigen palette) and `_mpl.png` (white + tab10) alongside
  `_dark.png` / `_light.png`.

### Export

* `savePng(const QString& path, int width, int height) -> bool`
* Offscreen rendering via `QRhi::beginOffscreenFrame()` and texture readback.
* Produces resolution-independent output at any specified size.
* Data geometry uses the QRhi path; text and UI overlays may be composited with
  `QPainter` before the final image is written.

### MSAA

* Pipelines respect `renderTarget()->sampleCount()`.
* Users enable MSAA via inherited `QRhiWidget::setSampleCount()`.

## Performance Targets

| Metric | Target |
|--------|--------|
| 2D line (1 M points) | ≥ 60 Hz sustained |
| 3D point cloud (500 K points) | ≥ 60 Hz sustained |
| 3D mesh (200 K triangles) | ≥ 60 Hz sustained |

| First frame after `plot()` | < 16 ms |

## License Verification Criteria

1. No translation unit includes a GPL-only Qt module header.
2. `QPainter` usage is limited to text and UI overlays; scientific data
  geometry does not use a software painter path.
3. No `QGraphicsScene` or `QOpenGLWidget` dependency.
4. Scientific data rendering passes through `QRhi` accessed via `QRhiWidget`.
5. Eigen is MPL2 — compatible with MIT.

## v1.0.0 Acceptance Criteria

Every required criterion below must pass or be explicitly waived in the
release notes with a linked issue and rationale. Aspirational roadmap items do
not block v1.0.0.

### Functional Acceptance

- [x] Every plot type in the v1.0.0 scope has a public API and runnable example
  or gallery coverage.
- [x] Scrolling telemetry uses fixed-capacity circular sample storage and the
  existing dynamic line-rendering pipeline.
- [x] The essential v1.0 usability surface above is implemented and documented:
  series handles, legends, axis limits, linear/log scales, line styles,
  markers, and deterministic input validation.
- [x] Multiple line/scatter/fill series compose in one view without changing
  earlier series data or style.
- [ ] `clear()`, individual series removal, telemetry restart, and widget
  destruction release all associated CPU and QRhi resources under sanitizer
  or platform-equivalent leak checking.
- [ ] Public methods are exercised with empty, singleton, mismatched,
  non-finite, and large inputs; behavior is documented and consistent across
  Debug and Release builds.

### Rendering Acceptance

- [ ] An automated offscreen gallery renders representative basic, filled,
  colormapped, text-overlay, telemetry, point-cloud, and mesh scenes.
- [ ] Every generated PNG decodes successfully, has the requested dimensions,
  contains non-background pixels, and has non-trivial color variation.
- [ ] Dark, light, paper, and matplotlib-style gallery output is reviewed at
  1x and 2x scale with no clipped labels, overlapping text, missing geometry,
  or unreadable contrast.
- [ ] Rendering smoke tests pass on Vulkan/Linux, Metal/macOS, and
  Direct3D/Windows. Pixel-perfect cross-backend equality is not required;
  structural image checks and approved visual baselines are.
- [ ] PNG export is deterministic in dimensions and scene contents for a fixed
  dataset, theme, viewport, and device-pixel ratio.

### Numerical Acceptance

- [ ] Tick locations are finite, monotonic, and cover the visible bounds for
  negative-only, positive-only, mixed-sign, tiny, large, and constant ranges.
- [x] Histogram counts conserve the number of finite observations; density
  integrates to 1 within floating-point tolerance.
- [ ] Box-plot quartiles/whiskers, violin KDE samples, hexbin counts, contour
  crossings, normals, and colormap samples have deterministic reference tests.
- [ ] Log scales reject or mask non-positive values according to one documented
  policy and never send NaN/Inf coordinates to the GPU.

### Performance Acceptance

- [ ] A versioned benchmark executable records CPU preparation time, upload
  time, first-frame latency, steady-state frame rate, and peak retained memory.
- [ ] The benchmark records 2D line (1 M points), telemetry (10 K retained
  samples), point cloud (500 K points), and mesh (200 K triangles).
- [ ] Measurements are recorded for one named release machine per native
  backend. Hardware, OS, Qt version, compiler, build type, resolution, MSAA,
  and vsync state are included with the results.
- [ ] The headline thresholds in **Performance Targets** are published as
  achieved results only where measurements pass. Otherwise documentation uses
  measured values and keeps the thresholds explicitly labelled as targets.
- [ ] Telemetry append performs no heap allocation after initialization when
  the configured window size is unchanged.

### Build, Package, and Compatibility Acceptance

- [x] Tagged releases publish a complete buildable source archive with a
  SHA-256 checksum.
- [x] Tagged releases wait for Linux, macOS, and Windows build-and-test jobs.
- [x] Staging installs the package and builds a downstream
  `find_package(SkigenPlot)` consumer.
- [ ] Static and shared library builds both configure, build, install, and link
  from a clean checkout with system Eigen and supported Qt versions.
- [ ] The installed-package consumer runs on Linux, macOS, and Windows and does
  not depend on source-tree paths.
- [ ] GCC 13/14, Clang 17+, AppleClang, and MSVC 19.38+ complete with zero
  project warnings under the documented warning profile.
- [x] Public headers do not include QRhi private implementation headers and
  compile in a downstream translation unit without repository-private paths.
- [ ] The release archive version, CMake package version, documentation
  version, Git tag, and changelog version all agree.

### Documentation and Release Acceptance

- [ ] Every public class and method has API documentation covering ownership,
  units, defaults, validation, and thread-affinity constraints.
- [ ] The getting-started guide is verified from a clean environment through
  configure, build, interactive display, PNG export, install, and downstream
  consumption.
- [ ] The gallery demonstrates every v1.0 plot type and links each image to
  buildable source.
- [ ] The documentation distinguishes measured performance from design targets
  and lists backend-specific limitations.
- [ ] `CHANGELOG.md` contains the release date, additions, behavior changes,

- [ ] The complete CI matrix is green on the release commit.

## Matplotlib Compatibility Roadmap

This roadmap is capability-based. New plot types should not outrun the shared
axes, composition, styling, testing, and accessibility infrastructure needed
to make them production-quality.

### v1.1 — Figure Composition and Publication Basics

- Introduce explicit `Figure`, `Axes`, and stable artist/series ownership with
  subplot grids, shared axes, constrained layout, and per-axes legends.
- Add text/annotation primitives, horizontal/vertical reference lines and
  spans, custom ticks/labels, minor ticks, grid styling, and spine control.
- Add SVG export and print-quality sizing/DPI semantics; evaluate PDF through
  a permissively licensed backend or native writer.
- Add symmetric-log scales, categorical axes, and basic date/time formatting.
- Add stack plots, stairs, ECDF, 2D histograms, event plots, and pseudocolor
  meshes.

### v1.2 — Scientific Breadth

- Add polar axes, spectral plots (PSD, spectrogram, coherence, correlation),
  stream plots, barbs, and richer error-bar forms.
- Add unstructured triangular plots (`triplot`, `tripcolor`, `tricontour`,
  `tricontourf`) using a proven triangulation library.
- Add image interpolation controls, normalization strategies (linear, log,
  symmetric-log, centered, boundary), custom colormap registration, and richer
  colorbar placement/ticks/labels.
- Add 3D lines, wireframes, parametric surfaces, trisurfaces, quiver, bars,
  contours, and voxels.

### v1.x — Interaction and Ecosystem Parity

- Add public pointer/keyboard event subscriptions, picking, hover data cursors,
  linked selections, brushing, and synchronized axes.
- Add animation/timeline support, general in-place data updates, pause/resume,
  and deterministic frame export.
- Add style sheets, named colors, reusable style contexts, font configuration,
  and accessible palettes.
- Provide adapters for `std::mdspan`, standard contiguous ranges, common point
  structures, and optional dataframe/table ecosystems without making them core
  dependencies.

### Beyond Matplotlib — GPU-Native Differentiators

- Automatic level-of-detail selection, min/max envelope decimation, and
  viewport-aware culling for datasets larger than GPU memory.
- Asynchronous and persistent uploads, multi-thread producer queues, and
  zero-allocation steady-state streaming with explicit backpressure.
- GPU-side histogramming, binning, transforms, colormap normalization, and
  selection for large interactive datasets.
- First-class high-rate multichannel telemetry, synchronized cursors, trigger
  markers, and rolling statistics for scientific instrumentation.
- Unified high-performance 2D/3D scenes, compute-assisted picking, large point
  clouds, and volumetric rendering.
- Deterministic headless rendering services and reproducible visual-regression
  metadata suitable for CI, reports, and remote compute nodes.
